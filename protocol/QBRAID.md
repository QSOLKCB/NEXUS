# Independent multicore verification protocol

This protocol lets an autonomous agent or a person verify a frozen NEXUS
commit on a multicore host such as a qBraid workspace and return an evidence
bundle whose every number is traceable to a raw file.

It is executed, not summarised. The harness in `scripts/verify_harness.sh`
implements it; `scripts/summarize.py` and `scripts/provenance.py` derive the
report tables and the version manifest from raw output.

## Separation of facts

The bundle must keep these as separate recorded fields and never conflate
them:

| Fact | Source |
|---|---|
| package version | `cargo metadata` of the tested checkout |
| declared minimum Rust version | `cargo metadata` (`rust_version`) |
| active compiler and Cargo | `rustc -Vv`, `cargo -Vv` |
| optional MSRV toolchain result | a separately captured build and test, or INCONCLUSIVE |
| protocol (control) commit | commit of the checkout the protocol was read from |
| tested source commit | detached checkout actually built |
| host-advertised CPUs | `nproc --all`, `lscpu` |
| effective CPUs | affinity mask, cpuset, cgroup quota |
| requested workers | the number passed to `--workers` |
| effective workers | the `effective_workers*` columns NEXUS prints |
| observed OS threads | sampled `/proc/<pid>/task` counts while running |
| completed command | exit status file |
| measured memory | `/usr/bin/time -v` maximum resident set size of the NEXUS child |

`VmPeak` is virtual address space and must not be labelled resident memory.

## Rules

1. Fresh parent directory, detached checkout of the frozen commit.
2. Every Cargo command receives an explicit absolute `CARGO_TARGET_DIR`
   outside the checkout. After every Cargo command the checkout must be
   clean (`git status --porcelain --untracked-files=all --ignored=matching`
   empty, no `target/`). Any violation writes `INVALID-run.txt` and stops.
3. No `cargo fix`, no `cargo fmt` without `--check`, no lockfile regeneration,
   no git commands that hide a dirty tree.
4. Equations, tolerances, cardinalities, iterations, batch sizes, the worker
   matrix, and acceptance rules are fixed by this document.
5. Every repetition is kept. Failures, timeouts, and outliers are preserved
   with exit statuses. Nothing is deleted or cherry-picked.
6. Summary tables are generated by the saved analysis script from raw CSV.
   `REPORT.md` quotes the generated tables verbatim.
7. No GPU. No replacement implementation. No cached or mocked results.
8. If fewer than two effective CPUs are available, multicore speedup and
   efficiency are classified INCONCLUSIVE, and the single-worker results are
   still reported.

## Interpretation boundary

NEXUS evaluates continuous `f64` geometry. Trits and lanes are labels. Lanes
do not create threads; workers do. Ledgers establish byte identity. Golden
ordering is an alternative ordering. Sonification is a mapping. The lattice is
a classical reversible state machine. Do not infer finite-field geometry,
qutrit physics, quantum computing, physical dimensionality, conservation laws,
or topological invariants from this test.

## Fixed experiment matrix

### Correctness

```text
nexus audit
nexus audit --cardinality 65536
nexus audit --cardinality 1048576
nexus audit --cardinality 16777216
nexus audit --cardinality 4294967296
nexus audit --cardinality 1000003 --strands 777        # non-divisible partition
nexus audit --ordering golden
nexus audit --workers W   for W in {1, 2, 4, 8, 16} ∩ {W <= effective CPUs}
nexus trace 17 10000
nexus trace 511 10000 --ordering golden
nexus events 17 1000
nexus lattice-verify 1024 --rounds 16
nexus lattice-verify 4096 --rounds 64
nexus atlas 1000000 --rounds 16
```

Acceptance: `nexus_error`, `antipodal_error`, `endpoint_error` exactly
`0.00000000000000000e0`; `gap_error` `0` for every uniform audit;
`eversion_sign_ok` `true`; parallel audits byte-identical to the sequential
audit except for `elapsed_ns` and worker rows; `restoration_mismatches` `0`
and `passed` `true` for both lattice verifications.

### Determinism

```text
nexus ledger 100000              x 3 runs
nexus ledger 100000 --ordering golden   x 3 runs
```

Acceptance: identical `root_sha256` across repetitions; uniform and golden
roots differ.

### Performance (5 repetitions each, all retained)

```text
nexus bench 1000
nexus bench 1000 --strands 4096
nexus bench-exec 2000 262144 W   for W in the permitted worker set
nexus lattice-run 65536 128
```

Workers are requested; the `effective_workers_min`/`max` columns are what
NEXUS actually used. Speedup is `parallel-batch` median elapsed at `W=1`
divided by median elapsed at `W`; efficiency is speedup divided by effective
workers.

### Memory

Each performance command runs under `/usr/bin/time -v`; record `Maximum
resident set size (kbytes)` of the NEXUS child. When `/usr/bin/time` is
absent, the harness samples `VmHWM` from `/proc/<pid>/status` every 10 ms and
records the method alongside the value.

### Thread observation

While `audit --workers W --cardinality 4294967296 --strands 16777216` runs at
the largest permitted `W`, sample `/proc/<pid>/task` every 20 ms and record
the maximum count. Compare with requested and effective workers; do not equate
them. The count includes the main thread.

## Deliverables

```text
<bundle>/
  PROTOCOL.md                      (this file, from the control checkout)
  00-provenance/{control-commit.txt, tested-source-commit.txt, raw/...}
  00-provenance/VERSION_PROVENANCE.json
  01-build/primary/{format-check,clippy,build-release,tests}.{log,exit-status}
  01-build/msrv/...                (optional; INCONCLUSIVE when absent)
  02-correctness/*.csv  *.exit-status
  03-parallel/*.csv  thread-observation/*.txt
  04-performance/raw/*.csv  *.exit-status
  05-determinism/*.csv
  06-memory/raw/*.time.txt
  analysis/{summarize.py, provenance.py, performance_summary.csv, memory_summary.csv}
  REPORT.md
  SHA256SUMS.txt                   (relative paths; `sha256sum -c` must pass)
```

The report title is `NEXUS <version> independent multicore verification`.
Every version string in `REPORT.md` must agree exactly with
`VERSION_PROVENANCE.json`.
